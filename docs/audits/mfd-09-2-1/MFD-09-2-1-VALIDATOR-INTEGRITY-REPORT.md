## A3. Root Cause Analysis: `validationPassed: false`

### Location

`data/audit/mfd-09-2-taxonomy-integrity.json`, line 135:
```json
"validationPassed": false,
```

### What Causes It

The `validationPassed` field is set to `false` by the upstream PowerShell audit script that generated this JSON file. It reflects the presence of:

1. **370 phantom references** (`phantomReferences` array, starting at line 143) — topic IDs referenced in mappings but not present in `topics.json`
2. **Bidirectional coverage discrepancies** (`bidirectionalCoverage` array, starting at line 3475) — asymmetric topic↔dimension relationships
3. **7 cross-report inconsistencies** (`crossReportInconsistencies` array, lines 17-25) — MFD-09.1 report counts diverging from actual file contents

### Why the Validator Doesn't Check It

The MFD-09.2 JS validator was **intentionally scoped** to verify:
- Structural integrity of production data (counts, distributions, relationships)
- Consistency between audit artifacts and source data
- That known issues (phantoms, discrepancies) are **properly documented**

Checks #38 and #39 explicitly verify that phantoms and discrepancies are *documented* (i.e., arrays are non-empty), treating their presence as expected state rather than failures. The validator does **not** read or evaluate the `validationPassed` field itself.

### Conclusion

The `validationPassed: false` flag and the validator's 39/39 pass result are **both correct within their respective scopes**:
- `validationPassed: false` = "Known integrity issues exist in the data" (upstream audit scope)
- Validator 39/39 = "All structural checks pass and known issues are properly documented" (MFD-09.2 validation scope)
